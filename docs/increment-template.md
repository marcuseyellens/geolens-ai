# 增量文档模板（Δ-01~Δ-07 / EX-14）

> 本模板是《CodeBuddy 执行规格书｜2026-11-16 AEO 增量批次》§4.4 与 EX-14 的
> 落库模板。**每个增量需求都必须引用本模板**；评审检查表有一项否决权：
> 未带三级标记、未写「证据来自哪一层」、或缺排除项清单的文档不得合入。
> `internal/delta/ci.go` 会校验本文件自身，缺字段即让 CI 变红。

## 三级证据标记

所有结论必须按下表标注，禁止把推导当作事实陈述。

- `[事实]` 平台公开文档或第一方明确给出的、可核验的陈述。
- `[观察]` 本平台在**答案层（answerlens_observation）**可观测到的原始答案、
  引用 URL 与访问日志证据，带 `run_id` / 证据 ID。
- `[推导]` 由观察作出的概率性判断、风险提示或建议，必须带来源链接与限定语。

**证据来自哪一层**：答案层（answerlens_observation）。本平台只记录可观测信号，
不声明任何模型内部检索机制，不把第一方自述或第三方转述当作实测。

## 结论写法

```
[事实] <平台公开说明，附来源链接>
[观察] <本次运行观测值，附 run_id / 证据 ID>
[推导] <概率性判断，附风险提示与来源链接>
```

三段各自独立，禁止合并成一段，禁止用 `[观察]` 承载 `[推导]` 的因果结论。

## 排除项清单

每份增量文档末尾必须逐条确认（可打勾，但不得删除条目）：

- [ ] 不声明模型内部检索机制（契约 9）。
- [ ] 不把 `user_provided` 指标混入图表、API 聚合、排序或均值（契约 10）。
- [ ] 不把 `suspect` 并入 `usable` / `failed`，四数互不折算（契约 11）。
- [ ] 不由 `registrable_domain` 反推 `host`，子域独立计数、不继承权重（EX-05）。
- [ ] 不把一种语言问题集直接翻译复用为另一种语言，两套独立计入配额（EX-03）。
- [ ] 不用平台提示文案作为 pass / fail 依据，结果页「平台提示」与「实际观察」分行（EX-08）。
- [ ] 不模拟爬虫、不伪造 UA 刷目标站日志；主动探测仅限用户自有站点且显式授权（EX-07 合规红线）。
